# conventions.md — units, field conventions, naming, style

Cross-cutting conventions the schema, registry, and scripts assume. Where a rule is mechanically
checkable it names the `validate.py` check; otherwise it is an authoring convention.

---

## 1. Units — stored as authored (SPEC §12, §11)

**The repo never auto-converts units.** Automated unit-system conversion is deliberately excluded
(conversion = error risk). Every entry stores values in the **unit system the source used**, and
tags that system.

- `units.system` (required): the unit system as authored, e.g. `cgs-gaussian`, `si`, `code`,
  `nondimensional`. Free string — the tag records provenance; it does not trigger conversion.
- All `parameters`, IC/BC expressions, and `reference_results.findings` are in the entry's authored
  system. `aux`/`material_fields`/`parameters` may carry an optional `units:` string for clarity.
- Quantitative findings are recorded **verbatim with units** wherever a reference reports them
  (SPEC §11.10).
- De-duplication compares the **canonical structural signature** (modulo numeric values, SPEC §2.1
  item 3), so two entries differing only by unit system still dedup correctly without conversion.

---

## 2. B-field convention

MHD entries must declare `units.b_field_convention` because the magnetic terms in the equations
differ by convention:

- `permeability-unity` — the SI-with-μ0=1 / Heaviside–Lorentz style where magnetic pressure is
  `B²/2` and `μ0` drops out.
- `sqrt-4pi` — the Gaussian style where fields absorb a `√(4π)` and magnetic pressure is `B²/8π`.
- Other conventions are permitted as strings; state them explicitly.

The convention is **stored, never converted** (as with units). When a source does not state its
convention, set `b_field_convention: null` and record a `needs-source` row in
`pending_extraction.md` — never guess it (SPEC §5.2, §11.5). The `magnetic-diffusion` induction
form `∂B/∂t = -(1/μ0)∇×(η∇×B)` assumes the coefficient is written for the declared convention.

## 3. Slug rules (SPEC §1.2)

- **kebab-case**, lowercase, ASCII, physically descriptive: `sod-shock-tube`,
  `orszag-tang-vortex`, `brio-wu-shock-tube`, `theta-pinch-compression`.
- Prefer the established physical name of the test. Spell out non-ASCII physics letters
  (`theta-pinch`, not `θ-pinch`; the informal `θ-pinch` lives only in the `/find-test` alias
  table, SPEC §7.3).
- The slug is the **stable public key** used in `/find-test` output and `related_to` links; it must
  equal the directory name `tests/<slug>/` and is not renamed lightly.
- One test = one directory `tests/<slug>/` with one `spec.md` + an `assets/` dir (SPEC §1.1).

---

## 4. Registry id naming

- Registry ids are kebab-case and match their filename: `registry/<kind>/<id>.md`.
- One markdown file per id, frontmatter + `## Definition / ## Params schema / ## Notes / ## Refs`
  (the format of the seeded solid-phase and `electromagnetic-coupling` files).
- Ids are physical descriptors only. **No numerical-method concept** ever becomes an id — most
  sharply for `internal-boundary-kinds` (physical couplings only; never `ghost-fluid`, `cut-cell`,
  etc.) (SPEC §1.6, §11.1).
- New ids are added only by the **hard-stop-and-propose** flow (SPEC §7.2); never invented silently
  inside an entry (SPEC §11.3).

---

## 5. Problem vs method boundary (SPEC §1.6, §11.1)

Reproduced here because it governs authoring style across every section:

- The **problem block** (frontmatter physics/geometry/ICs/BCs + the physical body prose) states the
  physics problem only: geometry, ICs, parameters, boundary conditions **as physical statements**,
  unit conventions, times.
- It **never** names a numerical method, resolution, AMR setting, or grid type. A spherical
  *coordinate frame the physics is posed in* is problem; a spherical *grid* is method.
- All method/resolution/AMR provenance lives in `reference_results` (`validate.py` check 7).

---

## 6. Style

- YAML frontmatter holds every structured/filterable field; markdown body holds prose only, in the
  fixed section order (`spec-schema.md` §2, SPEC §11.9).
- `spec.md` is one file, template-derived (`templates/spec.template.md`) — never freehand.
- `INDEX.tsv` is generated by `reindex.py` and **never hand-edited** (SPEC §11.4); a stale index
  fails `validate.py` (check 4).
- Keep comments in registry/spec files short and factual; cite the SPEC section they encode.
